One platform replacing spreadsheets, paper and scattered tools.

Growing companies run attendance, leave, payroll and hiring across Excel files and chat threads. PaySuite Workplace brings them into one governed system with rules that follow Bangladesh Labor Law and income tax requirements.

Where manual HR breaks

  • Manual payroll with repeated errors and rework
  • Leave and attendance rules applied inconsistently
  • No single record for audits and statutory files
  • No live view of headcount and cost for management

What changes with PaySuite

  • Policy-driven engines: rules are configured, not hard-coded
  • One employee record feeding every module
  • Role-based access with audit trails
  • Live dashboards for HR and senior management

Built like a product, run like a service.

The platform is multi-tenant: one master codebase is distributed to separate client deployments, each on its own Firebase project, so data stays isolated per organisation.

Security in two layers

Role-based access in the interface and again in 2,295 lines of Firestore security rules, plus separate Storage rules for uploaded files and input validation across forms.

Traceable by default

An audit log, an error log and an employee change ledger record who did what and when, so every figure can be explained in an audit.

Recoverable

Full-system backup export with restore, and a trash bin so deleted records can be brought back.

How a single action moves through the system

Every module reads and writes the same live Firestore database. There is no nightly sync, so the payslip, the chart and the audit log update the moment payroll runs.

  1. A role acts

    HR runs payroll, a manager approves leave, an employee checks in.

  2. Rules check

    Firestore Security Rules verify the role before any write is accepted.

  3. One record updates

    A single canonical document changes, so no copies drift apart.

  4. Screens redraw

    Live listeners push the change to every open screen in real time.

  5. Audit trail

    Who, what and when are logged for Admin and HR.

How a change reaches a client

A Deployment Manager shows differences, takes a backup and supports rollback before updates reach each client. Branding fallbacks stop developer branding from reaching customers.

  1. Build

    Change the master codebase.

  2. Check

    Run the standards script.

  3. Diff

    Compare against each client.

  4. Backup

    Snapshot before anything changes.

  5. Deploy

    Release with rollback ready.
